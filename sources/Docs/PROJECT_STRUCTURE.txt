RetroScraper project layout

The DPR and DPROJ stay at the repository root. Unit names are unchanged.
PAS/FMX pairs stay together in sources/UI. Application code is grouped in
sources/App, UI, Scraping, Library, Catalog, Settings, Media, Services and Common.
Tests, tools and documentation live in sources/Tests, sources/Tools and sources/Docs.

External source dependencies: dependencies/Delphi7z (Git submodule),
dependencies/HGM. The unrelated local dependencies/Player tree is retained by
explicit user choice; it is not referenced by the application or shipped.

Build resources: sources/Assets/Embedded (application icons and platform artwork).
Unused original C#/.NET sources, extracted UI graphics, reference styles and
localization drafts have been removed, along with the ILSpy decompiler and old
Skraper release notes/MIX manuals. Current FMX styles are embedded in UI forms.
Runtime resources: sources/Assets/Runtime/Resources and sources/Assets/Runtime/Mixes.
Resource directory names use RetroScraperLibrary2 and RetroScraperUI prefixes.
The registered workspace root remains
D:\Projects\SkraperFMX. Legacy config import and keyring identifiers are retained
for compatibility. Existing old settings copies are preserved as
RetroScraper.legacy.config.json when the current config already exists.
Loading also accepts that renamed legacy file. Older valid configuration schemas
are merged with missing defaults without resetting user settings. Existing
external MIX paths remain unchanged; missing built-in MIX paths from known old
application roots resolve to the current runtime tree. Original files are retained.
Resources/manifest.json lists the resource directories included in each package;
root resource files and all Mixes are also included. Backup/temp files are excluded
on every platform. Removed legacy systems images, loose unused icons, resource
extraction metadata and the redundant runtime ICO are not shipped.
PAS/FMX resources remain
with their units; the Delphi-generated project RES remains beside the DPR.

Build from any working directory:
  sources\Tools\build-target.cmd Win32 Debug
  sources\Tools\build-target.cmd Win32 Release
  sources\Tools\build-target.cmd Win64 Debug
  sources\Tools\build-target.cmd Win64 Release
  sources\Tools\build-platforms.cmd

Set BDS to override the RAD Studio installation directory. The default compiler
outputs remain .\$(Platform)\$(Config). Each successful build packages the EXE,
Resources, Mixes and LICENSE into dist/<Platform>-<Configuration>.
Package.ps1 can also be invoked separately without rebuilding.
package-desktop.py supports ZIP packages for Windows and bundles for Linux/macOS.
Tools contains only build.cmd, build-target.cmd, build-platforms.cmd, Package.ps1,
package-desktop.py, audit-assets.py, audit-locales.py, GenerateMixArtwork.dpr and
build-mix-checks.cmd. Obsolete UI generators, snapshots and temporary tool runtimes
have been removed. Asset audit reports are generated under Tests/Output/Audits.

Resource resolution checks the executable's directory first, then macOS bundle
resources, and the sources/Assets/Runtime tree for development builds.
User data are always outside the installation directory:
Windows: %LOCALAPPDATA%/RetroScraper, resolved through the OS known folder API.
Linux: $XDG_DATA_HOME/RetroScraper, otherwise ~/.local/share/RetroScraper.
macOS: ~/Library/Application Support/RetroScraper.
Legacy settings, credentials, catalog, logs and media indexes are imported without
modifying their source files. Portable Data is no longer a writable location.
POSIX keyring secrets are imported using their previous identity before saving
under the new user-data identity. Application/resource directories reject writes.

CacheFolder is a global setting, empty by default. API and ROM hash caches are
completely disabled until an absolute writable folder is selected in Settings.
Game media, previews and cache indexes then use that selected folder. CacheLimitGB
is global: default 10 GiB, 0 means unlimited. A background worker removes oldest
completed cache files by UTC modification time when the limit is exceeded.
Completed writes request maintenance, batched at most once per 30 seconds;
startup and saved policy changes request an immediate check. Active operation
leases protect only the files/directories currently in use; other old cache
entries remain eligible during long scraping runs. Incomplete downloads,
ROMs, exported media and unrelated files are excluded from automatic removal.
Platform icons, logos, wheels and photos are persistent user data under
PlatformArtwork/media with indexes in PlatformArtwork/index, independent of the
selected cache, its limit and cache clearing. Surviving old artwork is copied
from the selected cache at startup; source files are left unchanged. Artwork
also persists when caching is disabled. Downloads are validated before replacing
existing artwork. PlatformArtwork/update.json records UTC times of successful
refreshes and offers. Configured applications offer a catalog/artwork update at
startup after 14 days; declining also postpones the next offer by 14 days.
A successful manual or wizard refresh starts a new 14-day interval.
Necessary work
files without a cache use user-data Temp/<session GUID> and are removed at exit.
D:/Temp/RetroScraperCache is the explicitly selected cache on this workstation;
it is not a hardcoded default or shipped setting.
Distributables and ZIP archives exclude user settings, caches and credentials.

Self-tests use <user data>/Tests/AppData by default. RETROSCRAPER_TEST_DATA and
legacy SKRAPERFMX_TEST_DATA can select another test folder outside installation
and resources. Tests/build outputs still belong to sources/Tests/Output.

Build all maintained diagnostic probes for Win32 and Win64:
  sources\Tests\build-tests.cmd
  sources\Tests\build-tests.cmd Win64
The six SK.*Tests.pas units remain part of the application project. Twelve
standalone probes and two test build scripts are maintained in Tests; see its
README.md for commands. Generated binaries stay in Tests/Output (ignored by Git);
run-time fixtures, screenshots and reports use the selected test user-data folder.
Old archive probes for the removed SK.Archive.* backend were deleted; current
7z regressions use dependencies/Delphi7z via RunArchiveInputTests in
SK.Platform.Tests.pas, included in both Windows and portable self-tests.

Do not commit sources/Services/SK.ScreenScraper.Application.inc or dist/Data.
The example application include is safe to track. No commits or pushes were
performed by the reorganization.
